## 1. 目的与使用方式

本手册规定在 `rdma_rtl` 上做修改时的**影响分析、实现步骤、回归要求和文档同步规则**，避免“代码改了、测试过了、接口/语义/文档没同步”。

每次修改至少完成：影响分析 → RTL 修改 → testbench 更新 → 干净回归 → `CHANGELOG.md` 更新 → 功能手册/修改手册同步。

## 4. 修改流程

### 4.1 影响分析

| 检查项 | 问题 |
|---|---|
| 接口 | 端口名/位宽/方向是否变化？ |
| 参数 | 默认值/合法范围是否变化？ |
| 时序 | 延迟、脉冲宽度、握手是否变化？ |
| 语义 | ACK/NAK/重传/错误优先级是否变化？ |
| 文件列表 | 是否新增/删除 `.sv`？ |
| Testbench | 需要新增/修改哪些检查？ |
| 文档 | 功能手册、修改手册、CHANGELOG 是否要改？ |
| 集成 | 是否影响未来顶层连线？ |

### 4.2 RTL 修改原则

- 一次只改一个语义点；不要在同一提交里混合重构和功能变更。
- 保持 `rdma_pkg.sv` 中已有枚举编码不变；新增项追加到末尾。
- 时序逻辑统一 `always_ff @(posedge clk or negedge rst_n)`。
- 组合逻辑统一 `always_comb`，所有分支赋值，避免 latch。
- 新模块必须加入 `sim/filelist_rtl.f`。
- 新 testbench 必须加入 `sim/filelist_tb.f`，并更新 `TOP_MODULE`（如果换顶层）。
- 不在 RTL 中使用 `$display`/`$finish`。

### 4.3 Testbench 修改原则

- 驱动信号用 `@(negedge clk)`，采样用 `@(posedge clk)`，避免 posedge 竞争。
- 每个检查必须有明确的 `check(name, actual, expected)`。
- 新增测试组时同步更新检查数和文档。
- 不要为了通过而修改预期值；先确认协议语义。
- 对脉冲信号，在下一个 `negedge` 采样。

### 4.4 回归与文档

1. `make clean && make run`；
2. 确认 PASS/FAIL 和检查数；
3. 更新 `doc/CHANGELOG.md`；
4. 更新 `doc/功能手册.md` 的接口/行为/限制；
5. 更新本手册的“变更记录”和“待修项”；
6. 如接口变化，更新集成示例和检查清单。

## 6. 模块修改指南

### 6.1 `rdma_pkg.sv`

**不变量**：`BTH_W=80`、`RETH_W=128`、`AETH_W=32` 与结构体字段总和一致；已有 opcode/QP 状态/错误类型编码不得修改。

**规则**：新增 opcode 追加到枚举末尾，更新 `bth_gen` 使用方和 TB；修改位宽必须全项目搜索 `PSN_W/QPN_W/ADDR_W/RKEY_W`，同步端口、计数器、比较逻辑和 TB；新增错误类型追加到 `err_type_e` 末尾，更新 `error_detector` 优先级和文档。

### 6.2 `bth_gen.sv`

**不变量**：`hdr_en` 有效时 BTH 必须完整锁存；`bth_valid_o` 为单周期脉冲；固定字段 `se/m/pad_cnt/tver/f/b` 当前为 0。

**常见修改**：增加 PAD 需计算 `pad_cnt` 并明确字节序；增加 Immediate 需新增字段/数据通路，不能只改 opcode；增加 ready 会改变接口时序，必须同步 TB 和所有使用方。

### 6.3 `qp_fsm.sv`

**不变量**：状态只能逐级 INIT -> RTR -> RTS；`QP_ERROR` 只能通过 RESET 退出；`can_send` 仅在 RTS 为 1。

**注意**：`QP_SQE` 当前未使用；若要启用，必须定义进入/退出条件和 `can_send/can_recv` 语义；错误检测目前只在 RTS 生效，若要在 RTR/INIT 检测需明确协议行为。

### 6.4 `psn_manager.sv`

**不变量**：`base_psn <= head_psn`；`window_used = head_psn - base_psn`；ACK 只能把 `base_psn` 推到 `head_psn`；`MAX_RETRY/RNR_MAX <= 7`（当前 3 位计数器）。

**修改检查**：改窗口大小时确认 `WIN_SIZE` 与上层缓冲深度匹配；改重试上限大于 7 时必须加宽 `retry_cnt_r/rnr_retry_r` 和端口；改 ACK 语义时确认累计 ACK 范围和 PSN 回绕；当前任意 `ack_valid` 都会清除 `rtx_active`，建议改为“仅有效 ACK 清除”；当前 `timeout_i` 在 `rtx_active` 时被忽略，确认是否符合预期。

### 6.5 `rtx_buffer.sv`（优先修复）

**当前问题**：写索引使用 `buf_valid` 位图值；`usage_cnt` 是位图低 8 位；ACK 释放没有 PSN 回绕保护。

**建议修复方案**：

1. 增加 `wr_ptr_r`（`clog2(BUF_DEPTH)` 位）和 `count_r`（`clog2(BUF_DEPTH+1)` 位）。
2. 写入使用 `wr_ptr_r`，写后 `wr_ptr_r++`、`count_r++`。
3. `usage_cnt` 输出 `count_r`（按端口位宽截断/加宽）。
4. 重传查找仍按 PSN 线性搜索，或增加 PSN->entry 映射。
5. ACK 释放使用回绕安全比较：`(psn - base) < window` 形式，明确 24 位模运算。
6. 更新 Test 8：两次写入后 `usage_cnt=2`（不是 3）；ACK 后 `usage_cnt=1`；增加写满/回绕/重复 PSN 测试。

**验收标准**：连续写 N 条 `usage_cnt=N`；写满后有明确覆盖/拒绝策略；按 PSN 取回正确数据；ACK 后释放正确条目；`0xFFFFFF -> 0` 回绕正确；回归检查数只增不减。

### 6.6 `ack_timer_wheel.sv`

**不变量**：每 16 个时钟周期推进一个 slot；`timeout_val` 是 slot 偏移，不是时间单位；`timeout_pulse` 单周期。

**修改检查**：改 `SLOT_NUM` 同步 `SLOT_W`、`timeout_val` 截断和最大超时公式；改预分频同步文档、TB 等待时间和超时公式；解决冲突可增加 per-slot 链表、FIFO 或 per-QP 有效表，不能继续静默覆盖；start/cancel 同周期在集成层禁止，或在 RTL 中定义明确优先级。

### 6.7 `error_detector.sv`

**不变量**：优先级 `retry_exceeded > rkey > addr > rnr > link > icrc`；`err_valid/qp_reset_req/rtx_req` 为单周期脉冲；`err_type` 保持最近一次错误。

**修改检查**：新增错误需更新 `err_type_e`、优先级链、动作映射、TB、功能手册；若需锁存错误，增加 sticky 寄存器，不要依赖上层采样单周期脉冲；若需同时报告多个错误，当前结构不支持，需要改成位图/队列。

### 6.8 `icrc32.sv`

**不变量**：CRC-32C 反射多项式 `0x82F63B78`；初值 `0xFFFFFFFF`，输出取反；测试向量 `"123456789" -> 0xE3069283`。

**修改检查**：改多项式/字节序必须新增标准向量测试，不能只改代码；改握手需明确 `calc_start/data_valid/calc_done` 同周期优先级；提高吞吐需要并行 CRC 或流水线，不能简单改成多字节而破坏时序。

### 6.9 `dcqcn_rate_limiter.sv`（优先修复）

**当前问题**：`alpha_r` 初值 0，CNP 降速不生效；`max_rate_i` 未使用；token 不消费；增率溢出；Test 13 假通过。

**建议修复方案**：

1. `alpha_r` 初值设为非零（如 `8'd32`），或在首次 CNP 时置初值。
2. `rate_r` 复位为 `max_rate_i`，所有增率结果用 `min(max_rate_i, ...)` 夹住。
3. 增率使用饱和加法，避免 32 位回绕。
4. `tx_grant` 有效时扣减 token（或按包长扣减），并定义 token 下限。
5. 明确 `cnp_interval_i=0` 的行为（当前会每周期增率）。
6. 更新 Test 13：CNP 后速率必须下降；增率不能超过 `max_rate_i`；连续发送后 token 必须减少/授权受限。

**验收标准**：首次 CNP 后 `current_rate` 明显下降；多次 CNP 后不低于 `min_rate`；长时间无 CNP 不超过 `max_rate`；发送后 token 消费；无 32 位溢出；测试能区分“CNP 降速”和“溢出变小”。

## 7. 常见修改场景

### 7.1 新增一个 opcode

1. `rdma_pkg.sv` 的 `opcode_e` 末尾追加编码；
2. 检查 `bth_gen` 是否需要新字段；
3. TB 增加头部字段检查；
4. 更新功能手册 §3；
5. 更新 CHANGELOG。

### 7.2 调整发送窗口/重试次数

1. 修改 `psn_manager` 参数；
2. 确认 `MAX_RETRY/RNR_MAX <= 7`；
3. 更新 TB 的窗口/重试测试；
4. 更新功能手册参数表；
5. 回归 54+ 项。

### 7.3 增加错误类型

1. `rdma_pkg.sv` 追加 `err_type_e`；
2. `error_detector` 增加输入和优先级；
3. 明确 `qp_reset_req/rtx_req` 动作；
4. TB 增加错误注入；
5. 更新功能手册错误表。

### 7.4 调整 ACK 超时范围

1. 修改 `ack_timer_wheel.SLOT_NUM` 或预分频；
2. 更新最大超时公式和 TB 等待上限；
3. 确认 `start_qpn` 位宽随 `QP_NUM` 变化；
4. 更新功能手册时间模型。

### 7.5 更换 CRC 多项式/字节序

1. 修改 `icrc32` 的 next-state 函数；
2. 保留 `"123456789"` 向量并增加新向量；
3. 明确大小端和字节输入顺序；
4. 更新 TB 和功能手册。

### 7.6 增加顶层 `rdma_tx_engine`

建议顺序：

1. 先修复 `rtx_buffer` 和 `dcqcn` 的 P0 问题；
2. 定义顶层端口：时钟/复位、QP 命令、发送请求、ACK/NAK、错误、统计；
3. 连接 `qp_fsm -> psn_manager -> bth_gen` 和 `rtx_buffer`；
4. 接入 `ack_timer_wheel` 超时；
5. 接入 `error_detector`，明确锁存/清除；
6. 增加顶层 testbench：正常发送、ACK、NAK、超时、重试超限、错误注入；
7. 增加 SVA：窗口不溢出、PSN 单调、重传从 base 开始、QP_ERROR 后不发送。

### 7.7 增加 RX 路径

至少需要：`rx_transport_engine`（解析 BTH/RETH/AETH）、`icrc32_check`（校验入包 ICRC）、`aeth_parse`（解析 ACK/NAK/RNR）、`mpt_tlb`（RKEY/地址翻译）、`rx_dma`（写本地内存），并与 `psn_manager` 的 ACK 生成联动。

## 8. 编码规范

- 文件扩展名统一 `.sv`，每文件一个模块。
- 使用 `import rdma_pkg::*;` 共享类型。
- 端口命名：输入 `_i`、输出 `_o`、寄存器 `_r`、组合下一状态 `_n`。
- 时序逻辑统一 `always_ff @(posedge clk or negedge rst_n)`。
- 组合逻辑统一 `always_comb`，所有分支赋值，避免 latch。
- 参数位宽显式转换，避免隐式截断。
- 不在 RTL 中使用 `initial`、`$display`、`$finish`（TB 除外）。
- 新增模块必须加入 `filelist_rtl.f`。
- 新增检查必须更新通过标准中的检查数。
- 注释只写“为什么/约束”，不写显而易见的“做了什么”。

## 11. 故障排查

### 11.1 VCS 起不来

检查 `which vcs`、`$VCS_HOME`、`$LM_LICENSE_FILE`；确认已 `source /opt/tools/synopsys/env.sh`、已 `unset VCS_ARCH_OVERRIDE`、License 为 `27002@127.0.0.1`、使用 VCS 2023 而不是旧 VCS 2018。

### 11.2 编译报“找不到模块”

检查 `filelist_rtl.f` 是否包含新文件、`+incdir+../rtl`、package 是否先于使用它的模块编译。

### 11.3 仿真结果与预期不符

先确认 `make clean` 过；检查测试是否在 `negedge` 驱动；检查脉冲信号是否在下一个 `negedge` 采样；检查是否把“位图值”误当“计数”；检查 DCQCN 是否因溢出造成假下降。

### 11.4 FSDB 没有波形

检查 `dump_fsdb_vcs.tcl`、`simv -ucli -i ./dump_fsdb_vcs.tcl`、`tb_rdma_engine.fsdb`，以及 Verdi 与 VCS 版本匹配（当前 VCS 2023.12-SP1 / Verdi 2023.12-SP2）。

### 11.5 上传脚本破坏特殊字符

历史问题：PowerShell/plink 上传可能吞掉反引号、`$display` 等。建议在服务器端用 Python/heredoc 生成文件；上传后检查 `` `timescale `` 和 `$display`；不要用本地字符串插值直接拼接 RTL。

## 14. 维护原则

1. **先修 P0，再加功能**：`rtx_buffer` 和 `dcqcn` 未修复前，不建议继续堆叠顶层功能。
2. **测试必须能失败**：新增测试先确认在错误实现下会 FAIL，再确认修复后 PASS。
3. **文档描述实际行为**：不要把“计划实现”写成“已实现”。
4. **小步提交**：每次只改一个语义点，保留可回归的基线。
5. **接口变更必须全链路同步**：RTL、TB、文档、集成示例缺一不可。
